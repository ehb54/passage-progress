# Passage Progress

A small Chrome extension for reading long web pages in a group. It shows:

- **Page %**: how far through the page you've scrolled, plus "≈ N screens to go".
- **Passage %**: once you mark where the assigned passage **starts** and **ends**,
  your progress through just that stretch, with dashed START/END lines on the page.

The numbers appear in a small draggable meter in the corner of the page, in a thin
bar along the top edge, on the toolbar icon's badge (grey = page, green = passage), and
at the top of the page's right-click menu (e.g. **Passage 63% · Page 41%**).

The meter stays the same size when you zoom the page (⌘+ / Ctrl+), so zooming in to make
the text bigger doesn't make the meter cover more of it.

## Install (one time)

1. Get the files. On https://github.com/ehb54/passage-progress click **Code → Download ZIP**,
   then unzip it somewhere you'll keep it (Chrome loads the extension from that folder,
   so don't delete it). Or: `git clone https://github.com/ehb54/passage-progress.git`
2. Open `chrome://extensions` in Chrome.
3. Turn on **Developer mode** (top right).
4. Click **Load unpacked** and choose the unzipped folder (the one containing `manifest.json`).
5. Optional: click the puzzle-piece icon in the toolbar and pin **Passage Progress**.

To update later, replace the folder's contents with a fresh download (or `git pull`),
then click the reload ↻ icon on the extension's card in `chrome://extensions`.

It should also work in other Chromium browsers (Edge, Brave, Arc) via their own extensions
page, though it has only been tried in Chrome.

Tabs that were already open get the meter automatically. If one doesn't, reload it.
To read local `file://` pages too, open the extension's **Details** and turn on
**Allow access to file URLs**.

## Use

| To… | Do this |
| --- | --- |
| Mark the passage start | Right-click the first line → **Passage … · Page …% → Set passage START here** |
| Mark the passage end | Right-click the last line → **Set passage END here** |
| …or with the meter | Hover the meter → **Set start** / **Set end**, then click the line (Esc cancels) |
| …or with the keyboard | ⌥⇧S / ⌥⇧E (Alt+Shift+S / E), then click the line |
| Jump back to the start | Hover the meter → **Go to start** |
| Remove the marks | Hover the meter → **Clear**, or right-click → **Clear passage marks** |
| Hide/show the meter | Click the toolbar icon, press ⌥⇧P, or hover the meter → **✕** (the badge keeps working) |
| Move the meter | Drag it. Double-click to send it back to the corner |

Notes:

- If you set only a start, the passage runs to the end of the page. If you set only
  an end, it runs from the top.
- Marks are tied to the text itself, not to a pixel position. They stay on the right
  line when images load, the window is resized, or you zoom. They're saved per page
  address, so they come back if you reload or revisit the page.
- 0% means the START line is at the top of the window, and 100% means the END line
  has reached the bottom. This is the same rule as ordinary page scroll %.
- Keyboard shortcuts can be changed at `chrome://extensions/shortcuts`.

## Limitations

- **PDFs in Chrome's built-in viewer** and Chrome's own pages (`chrome://…`, the Web
  Store) don't allow extensions to draw on them.
- Content inside an **embedded frame** (some LMS pages put the reading in an iframe)
  isn't tracked. The meter follows the main page only. Opening the frame's content in its
  own tab works around this.
- Pages that draw text on a canvas (e.g. Google Docs) get a correct page %, but
  passage marks there are approximate (anchored by position, not by text).

## Privacy

Nothing leaves your browser. There are no network requests. Marks and settings are kept in
`chrome.storage.local` (the 500 most recently marked pages are retained). The "read and change
data on all websites" permission is what lets the meter appear on any page you read.

## Files

- `manifest.json`: extension manifest (Manifest V3)
- `background.js`: context menu, toolbar button, shortcuts, badge
- `content.js`: the meter, the marks, and the progress maths
- `icons/`: toolbar icons, generated by `tools/make_icons.py`
- `test/`: a stand-alone harness (`chrome-stub.js` fakes the extension APIs). To try it,
  run `python3 -m http.server` in this folder, then open `/test/test.html` (window-scrolled
  page) or `/test/inner.html` (app-style page that scrolls an inner panel)
